# VELOCITY expansion: audit, decisions and status

Written 2026-11-22 against the "Major Expansion & Android TV Edition" brief. It says what was found, what is
done and tested, what is not done, and what needs a decision from the owner. Nothing here claims TV support:
no TV hardware or Android SDK is available to test with.

## 1. Repository findings

| Area | Finding |
| --- | --- |
| Layout | `packages/shared` (simulation, catalog, rooms), `apps/client` (React 19, three r187, Vite), `apps/server` (Colyseus), `apps/mobile` (Capacitor 7), `apps/desktop` (Tauri 2). |
| Shared simulation | VELOCITY physics (`packages/shared/src/velocity`) is deterministic and shared by every client. One fixed wheel radius (`WHEEL_R` 0.36) and one wheel layout for all cars. The TV build must reuse it. |

| Build flavours | None yet. Paintball and VELOCITY are chosen by the mode switch on the Play screen (`state/ui.ts`). |
| Repository visibility | Public. Committing third-party models would redistribute them. |
| Back navigation, editor | Fixed earlier this session (see the commit log). |

## 2. The supplied cars (`Exported_Cars.zip`)

Extracted to `assets-src/cars-original/` and never modified. `assets-src/` is git-ignored.

Format: glTF 2.0 from Blender, one folder per car (`.gltf` + `.bin`), no textures. A −90° root rotation stands the
car up, nose toward −Z. Every car has the same seven meshes.

| Mesh | What it is | Notes |

| `Body` | underbody, shell parts | one material |
| `Paint` | the painted panels | one mesh, so no separate roof, doors, mirrors or spoiler |
| `Trim` | black trim | on some cars this holds the spoiler |
| `Window` | glass | |
| `Front` / `Rear` | head- and tail-lamp areas | |
| `Tires` | all four tyres as one mesh | split by the import script |
| `Rims` | two meshes (metal, dark insert), all four wheels each | split by the import script |

All seven are well under the 25,000-triangle budget. The full per-car manifest (part and material names,
original mesh/node names, bounding boxes, wheel centres, tyre widths, missing components, licence status) is
generated by `node scripts/process-cars.cjs` into `assets-src/cars-manifest.json`.

### Limits of the models, stated plainly

- **No separate roof, spoiler, mirrors, doors or brake calipers.** Accessories and body kit that need such
  geometry cannot be fitted to these cars. Only paint, trim, glass tint, lamps, rims, tyres, underglow and wheel
  glow apply today.
- **No usable UV layout.** The paint mesh reuses a few hundred UV coordinates across thousands of vertices, and
  `Body`/`Front`/`Rear`/`Trim` often have v collapsed to 1.0. Liveries, flags and numbers must be projected
  decals (planar/box projection in the car's space), not painted through UVs. That is not built yet.
- **Wheels are merged** in the source. The script splits them by connected pieces and assigns each to a corner.
- **Nose at −Z** in the source. The script turns every car to +Z.

## 3. Licence and naming

The files carry no author, source or licence text. On 2026-11-22 the owner confirmed they hold the rights to
redistribute all seven. That is recorded in the manifest (`licence.status: owner-confirmed`) and checked by a test.

- The original files stay local (`assets-src/`, git-ignored, large). The processed runtime models in
  `apps/client/public/models/cars/` (about 1.5 MB) are committed.
- The cars appear under invented names (for example "Kestrel Supercar"). No maker names or logos are in the game,
  and nothing claims an official affiliation. The makers' names appear only as lookup keys in
  `scripts/process-cars.cjs`. Say if you want the real names shown instead; that is a naming and trademark
  decision for you, not a technical one.

## 4. Done and verified in this phase

| Item | Evidence |
| --- | --- |
| Map-editor "Add point" crash | Root cause: the selected-point index outlived its point (undo, delete). Pure helpers in `packages/shared/src/velocity/trackEdit.ts`, wired into `TrackEditor.tsx`, 5 regression tests. |
| Import pipeline | `scripts/process-cars.cjs`: bakes transforms, orients to +Z, splits wheels, clamps tyre scale to 1.170–1.200 about each wheel centre, names parts and materials by role, writes GLBs and manifests. All 7 cars process without problems. |
| Runtime loading | `importedCars.ts` (GLTFLoader, optional `cars.json`), `registerBody` in the shared catalog, `CarModel.buildImported`. |
| Garage | All 7 cars appear (26 bodies total) and render with the real geometry, paint colour/finish, glass tint, rims. Checked in the browser. |
| Race | A race starts and runs with an imported car (screenshot at the grid). |
| Ground contact | For all 7 cars all four tyre bottoms land exactly on the physics contact height (−0.792 at 30% compression). Each wheel is lifted by its own radius minus the physics radius. |
| Tests | `importedCars.test.ts` (manifest: tyre band, four wheels, orientation, licence record; skipped if the source files are absent). Typecheck passes. |

Visual wheel positions follow each model's own axles, so a long car (the 5.2 m saloon) overhangs the physics box
a little. The simulation is unchanged.

2. **Phase 3, customisation:** projected decals/flags/numbers/names, per-car saved configs, second-colour channel

4. **Phase 5, audio:** per-car engine profiles, tyre squeal, surfaces, volume sliders, voice limits.
5. **Phase 6, tracks:** map themes in the editor, deterministic scenery placement that avoids road, grid and

   race (the Minimap expects a paintball view). Not caused by this work; not investigated.

## 7. Android TV edition (first cut, 2026-11-22)

One codebase, two Android apps. The TV app is a build flavor of the same Capacitor shell: package
`com.chromashift.game.tv`, label "VELOCITY", Leanback launcher with a banner, touch optional, landscape. It loads the
same live site as the phone app and tags the browser as `ChromashiftTV`, which switches on `tv.ts`/`tvFlag.ts`
(for testing on a computer, open the site with `?tv=1`; `?tv=0` turns it off). Nothing in the simulation, protocol
or servers changed, so it joins the same rooms as PC and phones.

CI (`android.yml`) builds `CHROMASHIFT.apk` (phone) and `VELOCITY-TV.apk` and attaches both to the `android` release.
The debug APKs are debug-signed, which is fine for installing with `adb install`.

| Requirement | State |
| --- | --- |
| VELOCITY only | Home shows Race, Garage, Settings; the Play screen has no game switch; the paint-shooter screens (`custom`, `online`, `locker`, `progression`, `profile`, `social`, `results`, `studio`) cannot be opened; invite links are ignored; the 3D menu is a plain backdrop. Limit: the shooter code is still inside the web bundle that the shell loads, it is just unreachable. A separate bundle would be a larger refactor. |
| D-pad menus | Spatial focus movement (unit-tested), OK activates, large focus ring. Controllers keep using the existing gamepad menu code. |
| Back key | In a race: pauses (the pause menu is the confirmation); in menus: goes back; at home: press twice to exit. |
| Simple remote mode | With no controller connected: the car accelerates by itself, Left/Right steer, Down brakes, OK uses an item, Back pauses. One-time hint on the first race. |
| TV graphics | First run: 720p, 30 fps cap, simple shadows, no bloom/AO/reflections/post. The viewport is already 960x540 CSS pixels at 2x, so text keeps its normal scale. |
| Bluetooth controllers | Uses the browser Gamepad API and the existing VELOCITY pad bindings. Not tested: no controller was connected to the TV. |

### Measured on the TCL TV (Android 11, `adb`)

Android 11 (API 30), armeabi-v7a only, 2 GB RAM, 1920x1080 (CSS viewport 960x540 at 2x), Mali-G31 with OpenGL ES 3.2,
System WebView 157. In the WebView: WebGL2 yes (max texture 4096, float render targets yes), WebRTC yes, WebAudio yes,
service workers yes, Gamepad API present. The first launch showed the sign-in screen (the game requires an account),
the app tag and TV mode were active, and the focus ring rendered. The old menu scene ran at about 20 fps there, which is why
the TV menu is now a plain backdrop.

### Not tested yet

- A VELOCITY race on the TV (frame rate, memory, sound, input): it needs an account sign-in on the TV, which only the
  owner can do. Frame rate in a race is the main open risk on this GPU and RAM.
- Online rooms between the TV and a PC or phone.
- Bluetooth controllers and the TV remote's real Back/OK keys (the code handles them; no one has pressed them).

Do not treat the TV as supported until those three are checked.
